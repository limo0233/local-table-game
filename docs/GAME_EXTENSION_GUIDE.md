# 局域网桌游新增游戏开发文档

> 目标：在现有《阿瓦隆》局域网桌游软件中新增 **TimeBomb、Crossfire、Good Cop Bad Cop、吹牛骰（Liar's Dice / Perudo）**。  
> 原则：**不破坏现有游戏；软件只做身份、私密信息、回合、操作确认和记录，核心交流仍在线下完成。**

---

## 1. 通用开发约束

### 1.1 必须复用
优先复用现有模块，不得为新游戏复制一套房间/网络体系：

- 房间创建 / 加入 / 房主权限
- 玩家昵称、座位顺序、准备状态
- WebSocket / 局域网通信
- 断线重连与状态恢复
- 游戏开始 / 结束 / 重新开局
- 公共游戏状态广播
- 玩家私密信息单独下发
- 历史记录
- 通用弹窗、确认按钮、倒计时组件
- 现有《阿瓦隆》逻辑保持独立，不因新增游戏产生行为变化

### 1.2 建议统一接口

```text
Game
├─ gameId
├─ phase
├─ round
├─ currentPlayerId
├─ players[]
├─ publicState
├─ privateState[playerId]
├─ history[]
└─ result
```

每个新游戏独立实现：

```text
GameConfig
GameState
startGame()
handleAction()
advancePhase()
checkWinCondition()
buildPublicState()
buildPrivateState(playerId)
```

### 1.3 UI原则

- 手机只显示“当前必须知道/操作”的内容。
- 不做复杂动画，不把桌游做成电子游戏。
- 讨论阶段尽量让玩家放下手机。
- 所有私密信息必须由后端按玩家单独发送，禁止前端拿到其他玩家隐藏数据。
- 关键操作必须由后端校验，不能只依赖前端按钮限制。

# 2. TimeBomb(时间炸弹)

**人数：4–8人｜开发难度：★☆☆～★★☆**

## 2.1 核心规则

### 阵营
- **夏洛特(Sherlock) 阵营**：找出全部 `[拆弹线]`
- **莫里亚蒂(Moriarty) 阵营**：让 `[炸弹]` 被剪中，或拖到规定轮数结束

### 线路
- `[安全线]`
- `[拆弹线]`
- `[炸弹]`：仅1张

基础规则：N名玩家时准备 **N张拆弹线 + 1张炸弹 + 安全线补足至5N张**，初始每人5张。

### 流程
1. 后端随机分配阵营。
2. 每名玩家查看自己当前持有线路的组成。
3. 系统将该玩家线路内部顺序重新随机，玩家只知道“有哪些”，不知道具体哪张是哪张。
4. 当前持有剪线钳的玩家选择**另一名玩家**的一条未知线路。
5. 系统翻开并公布结果。
6. 被剪线的玩家成为下一名行动玩家。
7. 每轮共剪线 N 次；轮末将未翻开的线路重新混洗、平均分配。
8. 最多4轮。

### 胜负
- 全部 `[拆弹线]` 被找到：Sherlock 胜
- `[炸弹]` 被剪中：Moriarty 立即胜
- 第4轮结束仍未拆完：Moriarty 胜

## 2.2 软件功能

### 前端新增
- 私密阵营页
- “我的线路组成”页
- 其他玩家剩余线路数量
- 当前持钳玩家高亮
- 选择玩家 → 选择线路 → 二次确认
- 公共翻线结果
- 当前轮次 / 已找到拆弹线数
- 历史：`A 剪了 B → 安全/拆弹/炸弹`

### 后端新增
- 阵营随机分配
- 线路池生成 / 洗牌 / 重分配
- 当前持钳玩家控制
- 禁止剪自己
- 每轮剪线次数统计
- 立即胜负判定

### 状态
```text
phase: ROLE_REVEAL | ROUND | CUT_RESULT | ROUND_RESET | GAME_OVER
wireCountsByPlayer
privateWires[playerId]
currentCutterId
cutsThisRound
defuseFound
round
```

# 3. Crossfire

**人数：5–10人｜开发难度：★★☆**

> V1只实现标准 **Crossfire Mode**，暂不实现 Sniper Mode 和扩展角色。

## 3.1 核心规则

### 基础身份
- `[VIP]`：蓝方核心目标，避免被射杀
- `[Agent]`：蓝方，保护VIP、识别并攻击Assassin
- `[Assassin]`：红方，目标是射杀VIP
- `[Bystander]`：中立平民，被误伤会影响射击者胜负
- 标准模式还可包含 `[Decoy] / [Red Decoy] / [Blue Decoy]`

> **角色数量按玩家人数配置，必须数据化，不得写死在流程逻辑中。V1角色配置按官方基础 Crossfire Mode 规则表实现。**

### 信息阶段
Crossfire的关键不是完全盲身份，而是“有限情报”：

1. 每人先查看一张初始角色。
2. 角色卡按规则向左传递，玩家查看经过自己手中的角色。
3. 按规则由指定位置对相邻角色进行随机混洗。
4. 玩家最后得到自己的最终身份。
5. 玩家根据自己曾看到的信息进行推理和撒谎。

### 讨论与射击
1. 开启约3分钟讨论计时。
2. 玩家主要面对面讨论，不要求持续操作手机。
3. 计时结束后，每人秘密选择一个射击目标/按角色执行对应动作。
4. 全员确认后统一锁定并同时结算。
5. 系统公布必要身份与结果。

### 基础胜负
- VIP被成功射杀：Assassin阵营达成核心目标
- VIP存活：Agent阵营达成核心目标
- Bystander、Decoy等按各自角色附加条件单独判定

## 3.2 软件功能

### 前端新增
- 初始身份查看
- “你刚刚看到的角色”提示
- 信息传递 / 混洗阶段确认
- 3分钟讨论倒计时
- 射击目标选择
- “已锁定，等待其他玩家”
- 统一结算页面
- 每名玩家最终胜/负结果

### 后端新增
- 按人数加载角色配置
- 信息传递与局部随机混洗
- 记录“某玩家合法看过哪些角色”
- 最终角色分配
- 所有人同时提交射击目标
- 提交完成前禁止泄露其他人的目标
- 统一射击结算与角色独立胜负判定

### 状态
```text
phase: INITIAL_VIEW | INTEL_PASS | SHUFFLE | DISCUSSION | TARGETING | RESOLVE | GAME_OVER
initialRoles
finalRoles
knownIntel[playerId]
discussionDeadline
targets[playerId]
lockedPlayers[]
resultByPlayer
```

# 4. Good Cop Bad Cop

**人数：4–8人｜开发难度：★★★**

> V1只实现基础游戏。扩展包、特殊晋升、僵尸等暂不开发。

## 4.1 核心规则

### 身份 / 阵营
每名玩家拥有3张 `[Integrity]` 身份信息牌。

主要类型：
- `[Honest]`
- `[Crooked]`
- `[Agent]`：Honest阵营首领
- `[Kingpin]`：Crooked阵营首领

阵营判断：
- 持有 `[Agent]` → Honest阵营
- 持有 `[Kingpin]` → Crooked阵营
- 否则由3张身份牌中 Honest / Crooked 的多数决定

### 每回合
当前玩家选择一个动作：

1. **Investigate 调查**  
   私下查看另一玩家1张未公开的Integrity。

2. **Equip 装备**  
   抽1张装备；若自己仍有隐藏Integrity，公开其中1张。

3. **Arm 武装**  
   获得枪；若自己仍有隐藏Integrity，公开其中1张，并选择瞄准目标。

4. **Shoot 射击**  
   射击当前瞄准目标，然后失去枪。

行动后，如仍持枪，可重新选择瞄准目标。

### 被射击
- 被射击后公开全部Integrity。
- 普通角色：首次中枪即淘汰。
- Agent / Kingpin：第一次中枪进入 `[Wounded]`；第二次中枪失败。

### 胜负
- Agent被第二次击中/淘汰：Crooked阵营胜
- Kingpin被第二次击中/淘汰：Honest阵营胜

## 4.2 软件功能

### 前端新增
- 3张Integrity私密/公开状态
- 调查：选择玩家 → 选择其一张隐藏Integrity → 私密查看
- Equip按钮与装备手牌
- Arm按钮、持枪状态、瞄准目标
- Shoot按钮
- Wounded / 淘汰状态
- 当前行动玩家
- 行动历史

### 后端新增
- Integrity牌池及随机分配
- 玩家阵营实时判定
- 每张Integrity的 `hidden / revealed`
- 调查权限控制
- 装备牌池与装备效果
- 枪数量、持有人、瞄准目标
- 受伤 / 淘汰 / 首领胜负判断

### V1装备策略
Good Cop Bad Cop 的装备卡会显著增加开发复杂度：

- **优先实现基础核心动作**
- 装备系统做成独立 `EquipmentEffect` 处理器
- 首批只加入必要/简单装备
- 不允许装备效果直接写进通用房间代码

### 状态
```text
phase: TURN | ACTION_RESOLVE | GAME_OVER
integrity[playerId][3]
team[playerId]
equipment[playerId]
gunHolder
aimTarget[playerId]
wounded[playerId]
eliminated[playerId]
currentPlayerId
```

# 5. 吹牛骰（Liar's Dice / Perudo）

**人数：建议2–6人｜开发难度：★☆☆**

> V1采用标准Perudo核心规则。`Calza（精确叫点）`先设计扩展接口，可默认关闭。

## 5.1 核心规则

### 目标
每人初始5颗骰子。每轮输家失去1颗骰子，最后仍有骰子的玩家获胜。

### 每轮
1. 所有存活玩家同时秘密掷骰。
2. 每人只能看到自己的骰子。
3. 起始玩家叫点，例如：`5个[4]`。
4. 下一玩家只能：
   - **加注**：提高数量，或在同数量下提高点数；提高数量后可重新选择点数
   - **Dudo / 质疑**
5. 有人质疑后，全员骰子公开并结算。
6. 若上一叫点成立（实际数量 ≥ 声明数量）→ 质疑者失去1骰。
7. 若叫点不成立 → 上一名叫点者失去1骰。
8. 失骰玩家通常成为下一轮起始玩家。
9. 骰子归零的玩家淘汰。

### `1`点规则
基础Perudo中 `[1]`（Paco）通常作为万能点，可计入其他点数。

### Palifico
玩家第一次只剩1颗骰子时，下一轮进入Palifico：
- `[1]`不再是万能点
- 起始叫出的点数通常锁定，本轮只能提高数量

### 胜负
最后仍持有至少1颗骰子的玩家获胜。

## 5.2 软件功能

### 前端新增
- 私密显示自己的骰子
- 所有玩家剩余骰子数量
- 当前叫点
- `[加注]` / `[质疑]`
- 加注数量和点数选择器
- 开骰结果
- 每轮输家提示
- 玩家淘汰与最终胜者
- 可选：Palifico明显提示

### 后端新增
- 安全随机掷骰
- 骰子仅下发给本人
- 叫点合法性校验
- `[1]`万能点统计
- 质疑结算
- 失骰 / 淘汰
- Palifico触发
- 起始玩家轮转

### 状态
```text
phase: ROLL | BIDDING | REVEAL | ROUND_END | GAME_OVER
diceCount[playerId]
privateDice[playerId]
currentBid
currentPlayerId
lastBidderId
palifico
eliminated[playerId]
```

# 6. 推荐开发顺序

| 顺序 | 游戏 | 难度 | 主要原因 |
|---|---|---:|---|
| 1 | **吹牛骰** | ★ | 状态最简单，可先验证新游戏插件/状态机框架 |
| 2 | **TimeBomb** | ★★ | 与阿瓦隆复用度高，私密信息+回合逻辑简单 |
| 3 | **Crossfire** | ★★ | 主要新增有限情报传递和同时提交 |
| 4 | **Good Cop Bad Cop** | ★★★ | Integrity、装备、枪、受伤/淘汰逻辑最多 |

开发时先完成通用 `Game Adapter / Game State` 接口，再逐个接入，不允许四款游戏各自复制房间和网络代码。

# 7. 基础测试与验收

## 7.1 所有游戏共同验收

- [ ] 新游戏可在现有游戏选择页创建房间
- [ ] 原《阿瓦隆》创建、加入、准备、开局、重开均不受影响
- [ ] 房主可开始/放弃/重新开局
- [ ] 玩家断线后可重新进入原座位并恢复正确状态
- [ ] 私密身份/骰子/线路不会发送给无权限玩家
- [ ] 非当前玩家无法伪造当前回合操作
- [ ] 重复提交不会导致重复结算
- [ ] 房间刷新或短暂断网不会导致状态重置
- [ ] 游戏结束后所有客户端结果一致
- [ ] 历史记录至少包含关键回合动作

## 7.2 TimeBomb

- [ ] 4–8人均可正常开局
- [ ] 每局仅1张炸弹
- [ ] 玩家不能剪自己的线
- [ ] 被剪玩家正确获得下一次行动权
- [ ] 每轮结束剩余线路重新随机
- [ ] 拆完全部拆弹线立即判Sherlock胜
- [ ] 剪中炸弹立即判Moriarty胜
- [ ] 第4轮结束可正确判定

## 7.3 Crossfire

- [ ] 5–10人按配置生成合法角色
- [ ] 初始信息、传递信息、最终身份互不混淆
- [ ] 讨论计时正常
- [ ] 射击目标在统一结算前保持隐藏
- [ ] 全员锁定后仅结算一次
- [ ] VIP / Agent / Assassin / Bystander及Decoy基础胜负正确
- [ ] 每名玩家可得到自己的最终胜负结果

## 7.4 Good Cop Bad Cop

- [ ] 4–8人正常生成3张Integrity
- [ ] Agent / Kingpin阵营优先级正确
- [ ] Investigate只能查看指定隐藏牌且仅本人可见
- [ ] Equip / Arm会按规则公开自己的Integrity
- [ ] 持枪、瞄准、射击状态正确
- [ ] 普通玩家首次中枪淘汰
- [ ] Agent / Kingpin首次中枪受伤、第二次结束游戏
- [ ] 装备效果不会破坏主回合状态

## 7.5 吹牛骰

- [ ] 每名玩家初始5骰且只能看到自己的骰子
- [ ] 非法加注会被后端拒绝
- [ ] 质疑后正确公开并统计全部骰子
- [ ] `[1]`万能规则正确
- [ ] 质疑输赢与失骰对象正确
- [ ] 玩家0骰后正确淘汰并跳过回合
- [ ] Palifico只在正确时机触发
- [ ] 最后一名存活玩家自动获胜

# 8. AI执行要求

1. **先读取并理解现有完整项目**，确认房间、玩家、WebSocket、游戏状态、阿瓦隆模块的真实目录与数据结构。
2. **在现有架构上增量开发**，不得为了新增游戏大规模重构已有稳定代码。
3. 先抽象最小必要的通用游戏接口；如果项目已经存在类似接口，直接复用，不重复创建。
4. 每完成一款游戏，先完成该游戏基础流程和验收，再开发下一款。
5. 不优先开发动画、复杂美术、扩展包、高级规则。
6. UI保持现有软件风格，移动端优先。
7. 所有随机、身份、骰子、线路和胜负判定以房主设备/后端为唯一可信源。
8. 最终交付：
   - 四款游戏完整源码
   - 必要的数据配置
   - 简短运行说明
   - 四款游戏基础验收结果
   - 不影响原《阿瓦隆》的回归测试结果

> **优先级：可稳定多人游玩 > 规则正确 > 断线重连 > UI美化。**
